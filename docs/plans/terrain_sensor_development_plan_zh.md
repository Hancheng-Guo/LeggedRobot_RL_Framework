## 二、采样定义

1. **读取同帧几何量。** 在 base 坐标系中取安装点 O、足端参考点 F 和表示重力反方向的单位向量 u。按机型配置名义机身离地高度 h，即 `reference_height`。瞄准时只使用安装外参、足端运动学和配置值。
2. **构造名义蜂窝。** 在与 base XY 平行的平面 z = −h 上取中心 C = (F.x, F.y, −h)。中心束沿**安装点 O 到蜂窝中心 C**发射。足端仅沿 base Z 抬起时，所有目标点和发射方向保持不变。蜂窝随 base 滚转和俯仰。
3. **生成各束方向。** 用轴坐标 (q, r) 保留满足 max(|q|, |r|, |q+r|) ≤ n 的点，按层号、r、q 排序，中心在首位。间距 d 默认为 0.12 m，外围层数 n 默认为 4，每足共 1 + 3n(n+1) = 61 束，最外角距中心 0.48 m。按下式预生成平面偏移，每帧从同一安装点瞄准各目标点 P。

   ```text
   P = C + (d * (q + r/2), d * sqrt(3) * r/2, 0)
   direction = normalize(P - O)
   ```

4. **测距并还原命中点。** 后端按需将起点和单位方向变换到世界系，在从安装点起算的 `max_distance` 内取最近地面交点。目标点只用于瞄准，交点可以在目标点之前或之后。沿束距离为 t 时，base 系命中点 H = O + t × direction。若读数为相机光轴深度 Z，对视场内的前向射线，t = Z / dot(direction, 光轴单位向量)，两个方向均在同一坐标系表达。
5. **计算观测。** 每束输出 dot(F − H, u)，足端高于命中点时为正。使用完整三维位移投影。有效高度可以为零，通过独立布尔掩码区分无效读数，按名义目标点索引保存结果。
6. **核验实际覆盖。** 记 θ 为射线与 −base Z 的夹角。对有效的向下射线，命中点与目标点在 base XY 内的偏移为 |H.z + h| × tan(θ)。参考平面处的点距由配置确定，实测点距随姿态和地形变化。验收时按蜂窝层分别统计有效率和横向偏移，并与配置间距对照。

足端顺序沿用 simulator 解析出的 `ModelContext.foot_geom_ids`。MuJoCo 使用 `foot_geom_names`，Isaac 使用 `foot_body_prim_paths`。安装点按现有足序配置，跨后端对照时核对足端参考点和安装外参。

### 张量布局与索引

- **每帧数据。** 高度和有效掩码均按 `[N, F, K]` 紧凑存储，分别对应环境、足端与采样点，使用相同的足序和点序。默认每足 `K = 61`。局部 reset 保持请求的环境行序。高度 obs term 裁剪、缩放和展平结果，处理后将无效高度填 `0`。掩码 term 按同一顺序输出 `0/1`。
- **静态映射。** 初始化时根据蜂窝配置生成并复用采样索引与轴坐标 `(q, r)` 的双向映射。计算局部高差或六邻域特征时按坐标查找邻居。六个相邻坐标的偏移为 `±(1, 0)`、`±(0, 1)`、`±(1, −1)`。
- **二维转换。** 下游需要二维张量时，将坐标 `(q, r)` 放到 `[r + n, q + n]`，将末维扩展为 `(2n+1) × (2n+1)`，再按同一索引取回。布局掩码标记哪些单元属于蜂窝，由配置决定。逐帧有效掩码标记蜂窝内哪些射线命中。
- **下游使用。** 逐足 MLP 可直接读取紧凑向量，六邻域卷积可使用邻接索引或二维张量，播放可复用采样偏移绘制射线布局。编码器由后续实验决定。

### 采样有效性

| 情况 | 有效性 |
|---|---|
| 跨出生地块、邻接块或进入外围平地 | 按射线实际命中的地面与沿束距离逐点判定 |
| 有限射线段内没有可用地面交点 | 对应点无效，包括超量程、越出地面覆盖和沿束方向未命中 |
| 足端位置或安装点位姿无效 | 对应足端的采样无效 |
| 安装点与某束目标点重合 | 该束方向无定义，对应点无效 |
| 射线超出传感器视场或可转向范围 | 对应点无效 |
| 基座姿态非有限 | 对应环境整帧无效 |
| 后端能力不匹配、查询失败或结果形状错误 | 通过现有错误处理流程报告 |

现有 `ground_valid`、`terrain_in_bounds` 和终止条目继续按各自定义工作。扫描无效比例可用于诊断。

## 三、职责分配与配置

| 位置 | 职责 |
|---|---|
| simulator 配置 | 通过可选的 `simulator_state_manager_config.terms.foot_terrain_scan` 启用足端扫描 |
| MuJoCo / Isaac 后端 | 读取并规范化现有物理状态，解析资产中显式命名的安装点，提供同帧基座位姿、安装点位姿、足端位置和后端求交能力 |
| `SimulatorStateManager` | 由 simulator 持有。按配置名从注册表构建状态 term，原样转交 simulator 等构造依赖，调用启用的 term 并按名称保存输出 |
| `foot_terrain_scan` 状态 term | 校验安装点、布局、视场与量程，预生成蜂窝偏移。使用同帧安装点和足端位置生成从安装点指向参考平面目标点的射线，通过 `GroundRayQueryProvider.query_ground_rays()` 从 simulator 取得命中距离，计算重力方向上的高度差和有效掩码。求交器由 simulator 随场景配置和持有 |
| `ModelContext` | 提供 simulator 解析出的足端索引顺序，以及 `state_term_output_shapes[term 名][输出名]`。足端扫描的两个输出均声明 `(F, K)`，供观测条目确定维数和校验依赖 |
| `SimulatorState` | 通过 `state.foot_terrain_scan_heights` 和 `state.foot_terrain_scan_valid` 读取启用的扫描输出，两者均为 `[N, F, K]`。动态字段按输出名查找，允许显式返回 `None`。未发布的字段触发 `AttributeError`，不同 term 声明同名输出时在 manager 构建阶段报错。`clone()` 和 `select()` 保留 `None`。`as_dict()` 按字段名导出张量，固定字段优先，值为 `None` 时省略该字段 |
| `TaskContext` 与 `TaskStateManager` | `TaskContext.state` 传递已组装的状态。task state term 可消费状态并更新步态相位等任务量 |
| `ObservationManager` | 注册只读的 `foot_terrain_heights` 和 `foot_terrain_heights_valid`，处理缩放、裁剪、无效填充，并按 simulator 解析出的足序展平为 `[N, F*K]` |
| runner、policy、课程 | 沿用现有命名切片和维数组装，按配置决定 actor、critic 读取哪些条目。课程继续分配地形、摩擦和命令 |

simulator 在模型和足端映射可用后构建 `SimulatorStateManager`，在 task 构建观测前发布已启用条目的输出形状。`get_state()` 先读取后端状态，再由 manager 对本次选中的环境运行状态 term 并组装结果。现有基础与派生物理字段沿用原采集路径。首版的足端扫描同步使用本次读取的物理状态。关闭后，结果与形状映射均省略该条目，射线查询为零。扩展 A 由 simulator 侧的 manager 和 term 管理采样时序与缓存。 [仿真接口](../../envs/simulators/base.py) · [环境 step 与 reset](../../envs/vector_env.py)

simulator YAML 负责选择采集项。安装点由资产定义，MuJoCo 使用机身下的命名 `site`，Isaac 使用机身下的命名 USD `Xform`。四足机型首版按足序引用四个安装点，下面以 ANYmal C 的逻辑名称作示例，Isaac 配置填写对应 Prim 路径。播放时使用独立的可视化标记显示安装点、中心束、视场边界和命中点。task 通过 `TaskContext.state` 消费输出。

```yaml
simulator_state_manager_config:
  terms:
    foot_terrain_scan:
      spacing: 0.12
      layers: 4
      mount_names: [scan_rf, scan_lf, scan_rh, scan_lh]
      reference_height: 0.50  # 示例值，按机型名义站高站立时安装点高度配置，单位 m
      max_distance: 2.0
```

以下配置合入 task YAML 的观测条目。 [观测构建](../../envs/tasks/managers/observation/base.py)

```yaml
observation_manager_config:
  terms:
    foot_terrain_heights: {clip_range: [-1.0, 0.6], scale: 1.0}
    foot_terrain_heights_valid: {}
```

开启扫描后，`spacing`（`d`，单位为米）和 `layers`（`n`，外围层数）默认分别为 `0.12` 和 `4`。各机型可根据腿部工作范围和地形尺度覆盖间距、层数及量程。每项扫描观测的维数是 `F*K`，ANYmal C 和 Go1 在默认布局下均为 244。初始化校验 `spacing` 有限且为正、`layers` 为非负整数，以及量程和总点数预算。

初始化校验安装点的数量、名称和归属，以及 `reference_height` 与 `max_distance` 为有限正数。量程从各安装点沿射线方向计量。视场和最大转向角按模拟的传感器规格配置。输出高度按第二章将从命中点指向足端的位移投影到重力反方向。

两个 obs term 直接消费同一份扫描结果。`foot_terrain_heights` 同时读取高度和有效掩码，处理裁剪、缩放、无效值填充与展平。`foot_terrain_heights_valid` 将同一掩码展平为独立的 0/1 观测，供策略按需使用。共用的无状态预处理可由两个 term 复用。配置了任一条目时，构建观测必须校验 simulator 已启用 `foot_terrain_scan`，缺少依赖时报出对应配置路径。

检查点校验覆盖间距、层数、点序、解析后的足端标识及顺序、参考点、安装点映射与外参、`reference_height`、视场、转向限制、输出参考系、量程和观测变换。即使张量尺寸相同，也需校验这些配置。例如改变间距会改变每个采样点对应的物理位置，重排配置中的足端会改变各观测切片对应的脚。跨机型复用扫描实现时，策略的恢复与部署仍按其训练时的模型和观测契约校验。

## 四、阶段 1：状态管理与平地基线

本章记录平行蜂窝原型的平面采样定义及验收结果。

### 目标

建立 simulator 层的状态构建入口和可选采集机制，用已知平面验证双后端共用的足端高度采样定义。

### 实施方案

1. 实现 `SimulatorStateManager` 及其可选状态 term 配置，接入 `get_state()` 的状态组装。实现 `foot_terrain_scan` 的蜂窝布局配置与校验，验证第 0 层、默认布局的 61 个唯一采样点、相邻中心距、六个角点的距离和固定点序。用足端位置和完整基座姿态生成射线，并通过解析平面求交验证命中距离、命中位置、相对高度投影和布尔掩码。
2. 用解析结果对照两组用例：机身倾斜但地面水平时，检查各束命中位置和平地上每足组内等高；机身与斜坡平行时，检查 `base Z` 相同的命中点投影后能反映斜坡高差。覆盖不同足端高度、航向、滚转和俯仰。
3. 覆盖全量、非连续索引、空选择和非有限输入。记录扫描关闭时的观测维数与每步查询次数，供后续回归对照。
4. 用 61 个不同的高度值和一组包含命中、未命中的有效掩码，验证 `61 点 → 9 × 9 → 61 点` 往返后的数值、点序与有效掩码一致。检查布局掩码包含 61 个位置，中心有六个邻居且均距中心 `0.12 m`。
5. 在足端位置可区分的用例中重排已配置的足端，验证两个扫描张量的足维按解析顺序同步重排。用不同足端数量的合成输入校验张量形状和观测维数推导。
6. 固定足端 XY 和基座姿态，仅改变足端 Z，验证射线起点和命中距离保持一致，而相对高度随之更新。用解析地面覆盖量程边界、超量程及 `base` 平面上方无交点的情况。

### 完成标准

同一状态得到固定点序和一致结果。紧凑与二维布局往返后保留数据、点序及有效性，六邻域索引通过距离校验。平地高度、量程边界和无效点符合本阶段的解析平面验收标准。关闭扫描时，原有物理字段与基线一致，扫描条目从结果和形状映射中省略，射线查询次数为零。

### 验收记录

- 公共测试覆盖蜂窝点序与二维往返、六邻域距离、非连续索引、空选择、量程边界、无效位姿和足序重排，并用解析水平面和倾斜平面对照命中距离及重力投影。首版配置校验的点数预算为每足最多 4096 点。 [足端扫描测试](../../tests/test_foot_terrain_scan.py)
- 真实平地验收使用 3 个 Go1 环境，经 YAML 配置分别启用和关闭扫描。该次验收使用 MuJoCo 静态水平面与 Isaac 默认平地。 [平地验收脚本](../../tests/manual/verify_foot_terrain_scan_plane.py)
- 两端启用扫描时均得到每足 61 点及 `(4, 61)` 的输出形状，扫描高度与实际足端相对平地的高度一致。关闭扫描时结果和形状映射均省略扫描条目，射线查询次数为零，现有 task 的观测维数保持 112。
- MuJoCo/core 回归 1301 项通过，Isaac/core 回归 1236 项通过，各跳过 11 项。两套 Pyright 均无错误和警告。本机运行 Isaac Sim 原生验收时使用 Conda DLL 路径和 `MKL_THREADING_LAYER=SEQUENTIAL`，解决 NumPy 加载时的 OpenMP 运行库冲突。扫描启用和关闭两次原生进程均以 `0` 退出。

## 五、阶段 2：机身传感器安装点资产

### 目标

为 ANYmal C 和 Go1 的双后端资产建立可定位、可视化的传感器安装点。

### 实施方案

1. 在每种机型的机身上为四只脚各定义一个命名安装点。MuJoCo 使用 MJCF `site`，Isaac 使用 USD `Xform`。按对应机型的足序记录名称、机身局部位置、朝向和前向轴。
2. 在两个后端的可视化窗口中显示安装点和朝向。比较同一机型在两个资产中的物理位置与坐标约定，在机身移位和滚转时检查标记随基座变换。可视化标记使用无碰撞几何。

### 完成标准

ANYmal C 和 Go1 都能在双后端加载安装点，名称与足序一一对应，位置和朝向可从资产读出并在窗口观察。核对添加安装点前后的关节、足端碰撞和地面接触配置。

### 安装点与验收记录

|---|---|---|---|---|
| ANYmal C | (0.460, −0.075, −0.096) | 沿机身中线左右、前后镜像 | `base` | `/Geometry/base` |

## 六、阶段 3：参考平面蜂窝迁移与平地复验

### 目标

将阶段 1 的平行蜂窝改为第二章的机身安装点参考平面蜂窝，使用水平面建立新的双后端基线。

### 实施方案

1. 由 simulator 解析阶段 2 的安装点映射并提供同帧位姿。更新 `foot_terrain_scan` 的配置与射线输入契约，按足序生成共享起点和逐束方向。沿用现有状态管理入口及 `[N, F, K]` 高度和有效掩码输出。
2. 更新平面解析求交、配置校验、单元测试和原生平地验收脚本。用独立几何计算对照发射方向、命中位置、距离及重力投影。播放验收显示安装点、中心束、视场边界和命中点。

### 完成标准

机身固定时，单脚 XY 平移只改变该脚的瞄准方向。仅改变足端 Z 时，各束方向与距离保持一致，高度差按足端位移的重力投影更新。侧倾站在水平面时，同足各有效束等高；机身与坡面平行时，输出反映坡面高差。检查提前命中、越过目标点后命中以及外圈横向偏移与第二章公式的一致性。两端在平地上通过机身滚转、足端远近变化、视场边缘、量程端点、无效输入及局部环境读取验收。有效命中与解析结果一致，关闭扫描时沿用阶段 1 的观测维数和查询次数基线。

## 七、阶段 4：双后端地形扫描与训练集成

### 目标

将阶段 3 验收的参考平面蜂窝接入实际地形和现有观测框架，交付 Isaac 共享地形 GPU 批量求交及可复测的 PPO 短训与吞吐基线。

### 实施方案

1. **MuJoCo。** 每个环境按安装点用 `mj_multiRay()` 批量查询方向，使用限定地面几何的过滤配置。覆盖高度场、外围平地和自定义静态地面。验收范围边界和未命中。 [MuJoCo 批量求交接口](https://mujoco.readthedocs.io/en/3.11.0/APIreference/APIfunctions.html#mj-multiray)
2. **Isaac Sim。** 使用共享碰撞网格的同一份顶点和三角面，在场景初始化时构建 GPU 加速结构。批量接收逐束方向，起点、方向、查询和结果全程留在 GPU。局部读取只查询选中环境，课程换区时复用同一加速结构。用 PhysX 场景查询作为距离和有效性的原生对照，覆盖邻接块、外围和越出地图。
3. **观测及状态。** 注册两个足端观测 term，验证缩放、无效填充、足序及展平顺序。验证首次与局部 reset、失败回滚、终止帧、检查点续训，以及摩擦随机化和课程换地形。检查点校验第三章的采样契约。
4. **训练及性能。** ANYmal C 在两端各执行一次真实 PPO 短训，验证评估和播放。Go1 通过配置运行平地和斜坡的 reset 与 step 验收。以相同环境数、地形、采样配置和控制步长测量启闭扫描的预热后吞吐，Isaac 另对照同批射线的 PhysX 与 GPU 求交耗时，并记录峰值显存。

### 完成标准

- 两端用独立三角面对照斜向射线、接缝、外围、越界和局部 reset。有效掩码与参考结果一致，射线距离和投影高度的绝对误差在 `5e-5 m` 内。Isaac 共享地形的 CUDA 短训默认使用 GPU 求交，同规模求交耗时低于 PhysX 对照。
- 两个观测条目按配置进入策略。PPO 产生有限的观测、损失和参数更新。恢复后观测可复现，播放窗口可核对采样几何，两端均有可复测的吞吐基线。

## 八、扩展 A：采集时序与缓存

### 目标

让扫描具有独立于控制步的采样频率、可配置的交付延迟和逐环境缓存，为机载传感器的异步采集提供统一时序。

### 实施方案

1. 先在仿真中用固定采样周期和固定延迟验证机制。按仿真时钟调度，分别记录每帧的采集时间和可用时间。重复读取同一时刻的状态应复用已有采集结果。
2. 按环境缓存已采集帧及其姿态、有效性和时间戳，读取时使用最近一帧已可用的数据。首帧尚未可用或数据超龄时输出无效掩码。明确缓存的是整帧扫描还是可供当前射线重新查询的地表。
3. 局部 reset 清理选中环境的旧帧和待交付数据，失败时随 reset 回滚。检查点保存可复现后续采集所需的时钟、待交付帧和缓存。

### 完成标准

采样和交付时刻符合配置。重复读取、不同采样与控制频率、首帧等待、超龄、局部 reset、回滚和检查点恢复均有对照用例。零延迟且每控制步采样时与同步基线一致。

## 九、阶段 5：性能与交付

### 目标

量化几何查询在常用训练规模下的开销，以及仿真机载扫描的更新频率、延迟与有效覆盖率。确定可复跑的训练配置和验收入口。

### 实施方案

1. **训练路径。** 对照阶段 4 的吞吐基线复测。双后端均使用仿真地面几何查询，比较启闭扫描时的初始化时间、控制步吞吐、局部 reset 时间和峰值内存或显存。先测 1 和 16 环境，再测各后端常用规模，Isaac 增测 1024 环境。
2. MuJoCo 单独测量 CUDA 策略下的 CPU 往返和各安装点的批量求交。Isaac 使用阶段 4 交付的 GPU 批量求交，记录求交耗时和峰值显存。默认蜂窝布局在 1024 个四足环境中每帧查询 249,856 束。记录实际间距、层数、名义机身离地高度和量程。若需降频，补齐帧龄、坐标对齐和局部 reset 后首帧的处理与验证。
3. **感知路径。** 在少量 Isaac 仿真环境中测试机载扫描。记录扫描更新频率、从仿真采集到策略可用的延迟，以及四足采样点的有效比例。覆盖平地和移动场景。
4. 交付 ANYmal C 双后端训练示例、Go1 双后端复用示例、验收脚本和性能记录。训练记录注明机型、硬件、点数、控制步长、预热和运行长度。感知记录注明传感器配置、测试场景和延迟测量方法。

### 完成标准

双后端训练配置通过功能验收，并达到基于阶段 4 数据确定的吞吐与资源预算。仿真机载扫描有更新频率、延迟和有效覆盖率的测量记录。Windows 上 Isaac 验收进程的实际退出码为 `0`。使用交付配置和脚本可复跑。
