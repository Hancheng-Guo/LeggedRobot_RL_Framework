## 一、第一版目标

为多种足式机器人提供同一套足端扫描接口。在每只脚周围按 `base` 坐标布点，沿 `−base Z` 求交，输出命中点相对该足端沿重力对齐坐标系的高度差。MuJoCo 使用各环境的独立地形，Isaac Sim 使用共享地形图。采样结果通过可选的 `foot_terrain_heights` 和 `foot_terrain_heights_valid` 观测条目接入策略。首版直接查询仿真地面几何，覆盖平地、斜坡、粗糙地形、外围平地及 Isaac 跨地块行走。 [公共状态](../../envs/simulators/utils/state.py) · [仿真接口](../../envs/simulators/base.py)

ANYmal C 是主要训练对象和首个双后端完整验收机型。Unitree Go1 用于验证机型切换，沿用现有双后端配置，通过各机型的足端映射和采样参数接入同一套扫描与观测。扩展 B 以 ANYmal C 为首个实机验收对象。 [Go1 MuJoCo 配置](../../configs/simulators/mujoco_unitree_go1_rgb_array.yaml) · [Go1 Isaac 配置](../../configs/simulators/isaac_sim_unitree_go1_headless.yaml)

Miki 等人的实机方案从局部高程图采集足端周围的高度。本项目首版在每只脚周围使用蜂窝布局，默认相邻六边形中心间距为 0.12 m，中心外保留 4 层。虚拟深度相机和实机高程图沿用同一套采样位置。 [Miki 等人的论文及补充材料](https://arxiv.org/html/2201.08117)

## 二、采样定义

| 步骤 | 计算方式 | 用处与注意点 |
|---|---|---|
| 1. 用足端 XY 布置采样束 | 由同帧运动学得到足端在 `base` 中的 XY，在每只脚周围加固定偏移 `(dx, dy)`，采样束沿 `−base Z` | 蜂窝各点在机身中的相对位置固定。滚转和俯仰会改变各束在地面上的实际命中位置 |
| 2. 求命中点的 `base Z` | 在 `base Z = 0` 的平面上沿 `−base Z` 发射，找到 `max_distance` 内最近的地面交点。命中点的 `base Z` 等于沿束距离取负 | 可命中足端上方且位于射线段内的地形。台阶边缘的命中位置可能随姿态切换 |
| 3. 读取足端的 `base Z` | 取步骤 1 同一次运动学结果的 Z 分量，用于计算与命中点的高度差 | XY 和 Z 使用同一参考点和同一时刻。采用碰撞几何中心时，脚接触地面后仍可能有高度差 |
| 4. 计算 `base` 下的相对位移 | 计算 `dz = ground_base_z - foot_base_z`，组成完整位移 `(dx, dy, dz)` | XY 偏移由蜂窝布局给定，机身倾斜时也会贡献重力方向的高度差 |
| 5. 输出重力对齐的相对高度 | 用本帧姿态旋转完整位移，再取与重力反向的分量。地面低于该脚时为负 | 同一只脚的各束命中同一个水平面时，高度差一致。计算只需要相对重力的姿态，无需绝对世界位置 |

```text
ray_origin_base = (foot_base_x + dx, foot_base_y + dy, 0)
ray_direction_base = (0, 0, -1)
ground_base_z = -hit_distance
dz = ground_base_z - foot_base_z
relative_height = (R_gravity_from_base @ (dx, dy, dz))_z
```

例如，机身绕 X 轴滚转 30°，同一只脚的两束在 `base Y` 上相差 0.20 m，且都命中平地。第二个命中点的 `base Z` 低约 0.115 m。旋转后，Y 偏移贡献约 +0.10 m，Z 偏移贡献约 −0.10 m，两束得到相同的相对高度。四只脚离地高度不同时，各组的常数可以不同。机身平面与斜坡平行时，命中点的 `base Z` 可以相同，而旋转后观测仍会反映命中点的世界竖直高差。

**蜂窝布点。** 每个六边形中心对应一束射线。给定相邻中心距 `d` 和外围层数 `n`，枚举整数轴坐标 `(q, r)`，保留层号 `max(|q|, |r|, |q+r|) ≤ n` 的坐标。中心 `(0, 0)` 为第 0 层，包含在采样中。将每个坐标转换为 `base XY` 偏移：

```text
dx = d * (q + r / 2)
dy = d * sqrt(3) * r / 2
```

点序按层号、`r`、`q` 依次升序，中心点在首位。每足共有 `K = 1 + 3n(n+1)` 束，六个角点的最远中心距为 `n*d`。默认 `d = 0.12 m`、`n = 4`，每足 61 束，最远 0.48 m。

足端数量 `F` 和顺序沿用 simulator 解析出的 `ModelContext.foot_geom_ids`。MuJoCo 使用 `foot_geom_names`，Isaac 使用 `foot_body_prim_paths`，省略时沿用各后端现有的足端识别规则。扫描 term 与观测共享这一顺序。两端对照或复用同一个策略时，由各自配置将相同的物理足端排在同一位置，并核对参考点和姿态约定。实机取正运动学位置，仿真复用同帧的足端位置和基座位姿，必要时将世界位置逆变换到 `base`。 [ANYmal C MuJoCo 配置](../../configs/simulators/mujoco_anymal_c_rgb_array.yaml) · [仿真模型上下文](../../envs/simulators/utils/context.py)

### 张量布局与索引

- **每帧数据。** 高度和有效掩码均按 `[N, F, K]` 紧凑存储，分别对应环境、足端与采样点，使用相同的足序和点序。默认每足 `K = 61`。局部 reset 保持请求的环境行序。高度 obs term 裁剪、缩放和展平结果，处理后将无效高度填 `0`。掩码 term 按同一顺序输出 `0/1`。
- **静态映射。** 初始化时根据蜂窝配置生成并复用采样索引与轴坐标 `(q, r)` 的双向映射。计算局部高差或六邻域特征时按坐标查找邻居。六个相邻坐标的偏移为 `±(1, 0)`、`±(0, 1)`、`±(1, −1)`。
- **二维转换。** 下游需要二维张量时，将坐标 `(q, r)` 放到 `[r + n, q + n]`，将末维扩展为 `(2n+1) × (2n+1)`，再按同一索引取回。布局掩码标记哪些单元属于蜂窝，由配置决定。逐帧有效掩码标记蜂窝内哪些射线命中。
- **下游使用。** 逐足 MLP 可直接读取紧凑向量，六邻域卷积可使用邻接索引或二维张量，播放可复用采样偏移绘制射线布局。编码器由后续实验决定。

### 采样有效性

| 情况 | 有效性 |
|---|---|
| 跨出生地块、邻接块或进入外围平地 | 按射线实际命中的地面与沿束距离逐点判定 |
| 有限射线段内没有可用地面交点 | 对应点无效，包括超量程、越出地面覆盖和沿束方向未命中 |
| 某只脚的位置非有限 | 对应足端的采样无效 |
| 基座姿态非有限 | 对应环境整帧无效 |
| 后端能力不匹配、查询失败或结果形状错误 | 通过现有错误处理流程报告 |

现有 `ground_valid`、`terrain_in_bounds` 和终止条目继续按各自定义工作。扫描无效比例可用于诊断。

## 三、职责分配与配置

| 位置 | 职责 |
|---|---|
| simulator 配置 | 通过可选的 `simulator_state_manager_config.terms.foot_terrain_scan` 启用足端扫描 |
| MuJoCo / Isaac 后端 | 读取并规范化现有物理状态，提供本帧基座位姿、足端位置和后端地面求交能力 |
| `SimulatorStateManager` | 由 simulator 持有。根据配置构建状态 term，接收后端本次读取的状态，调用已启用的 term 并组装 `SimulatorState` |
| `foot_terrain_scan` 状态 term | 校验布局与量程，预生成蜂窝偏移。使用同帧姿态和足端位置生成射线，调用后端地面求交，计算重力方向上的高度差和有效掩码 |
| `ModelContext` | 提供 simulator 解析出的足端索引顺序及已启用扫描的每足采样点数，供观测条目在初始化时确定维数和校验依赖 |
| `SimulatorState` | 提供可选的 `foot_terrain_scan_heights` 与 `foot_terrain_scan_valid`，均为 `[N, F, K]`。高度已经是重力方向上的足端相对高度，沿用运行时 dtype 和 device，掩码为布尔值。验证 `clone()`、`select()` 和缓冲复用 |
| `TaskContext` 与 `TaskStateManager` | `TaskContext.state` 传递已组装的状态。task state term 可消费状态并更新步态相位等任务量 |
| `ObservationManager` | 注册只读的 `foot_terrain_heights` 和 `foot_terrain_heights_valid`，处理缩放、裁剪、无效填充，并按 simulator 解析出的足序展平为 `[N, F*K]` |
| runner、policy、课程 | 沿用现有命名切片和维数组装，按配置决定 actor、critic 读取哪些条目。课程继续分配地形、摩擦和命令 |

simulator 在模型和足端映射可用后构建 `SimulatorStateManager`，在 task 构建观测前发布扫描元数据。`get_state()` 先读取后端状态，再由 manager 对本次选中的环境运行状态 term 并组装结果。现有基础与派生物理字段沿用原采集路径。首版仅将足端扫描作为可配置的状态 term，同步使用本次读取的物理状态。扫描关闭时，两个扫描字段为 `None`，跳过射线查询。扩展 A 由 simulator 侧的 manager 和 term 管理采样时序与缓存。 [仿真接口](../../envs/simulators/base.py) · [环境 step 与 reset](../../envs/vector_env.py)

simulator YAML 负责选择采集项。task 继续使用现有接线和 `TaskContext.state`，通过观测配置选择要消费的数据。

```yaml
simulator_state_manager_config:
  terms:
    foot_terrain_scan:
      spacing: 0.12
      layers: 4
      max_distance: 2.0
```

以下配置合入 task YAML 的观测条目。 [观测构建](../../envs/tasks/managers/observation/base.py)

```yaml
observation_manager_config:
  terms:
    foot_terrain_heights: {clip_range: [-1.0, 0.6], scale: 1.0}
    foot_terrain_heights_valid: {}
```

开启扫描后，`spacing`（`d`，单位为米）和 `layers`（`n`，外围层数）默认分别为 `0.12` 和 `4`。各机型可根据腿部工作范围和地形尺度覆盖间距、层数及量程。每项扫描观测的维数是 `F*K`，ANYmal C 和 Go1 在默认布局下均为 244。初始化校验 `spacing` 有限且为正、`layers` 为非负整数，以及量程和总点数预算。

`max_distance` 是从 `base` 平面沿 `−base Z` 查找地面的最大距离，单位为米。设为 `2.0` 时，查询覆盖 `base Z ∈ [−2.0, 0] m`。量程内没有交点时，该点无效。输出高度按第二章将命中点相对足端的完整位移投影到重力方向。

两个 obs term 直接消费同一份扫描结果。`foot_terrain_heights` 同时读取高度和有效掩码，处理裁剪、缩放、无效值填充与展平。`foot_terrain_heights_valid` 将同一掩码展平为独立的 0/1 观测，供策略按需使用。共用的无状态预处理可由两个 term 复用。配置了任一条目时，构建观测必须校验 simulator 已启用 `foot_terrain_scan`，缺少依赖时报出对应配置路径。

检查点校验覆盖间距、层数、点序、解析后的足端标识及顺序、参考点、射线方向、输出参考系、量程和观测变换。即使张量尺寸相同，也需校验这些配置。例如改变间距会改变每个采样点对应的物理位置，重排配置中的足端会改变各观测切片对应的脚。跨机型复用扫描实现时，策略的恢复与部署仍按其训练时的模型和观测契约校验。

## 四、阶段 1：状态管理与平地基线

### 目标

建立 simulator 层的状态构建入口和可选采集机制，用已知平面验证双后端共用的足端高度采样定义。

### 实施方案

1. 实现 `SimulatorStateManager` 及其可选状态 term 配置，接入 `get_state()` 的状态组装。实现 `foot_terrain_scan` 的蜂窝布局配置与校验，验证第 0 层、默认布局的 61 个唯一采样点、相邻中心距、六个角点的距离和固定点序。用足端位置和完整基座姿态生成射线，并通过解析平面求交验证命中距离、命中位置、相对高度投影和布尔掩码。
2. 用解析结果对照两组用例：机身倾斜但地面水平时，检查各束命中位置和平地上每足组内等高；机身与斜坡平行时，检查 `base Z` 相同的命中点投影后能反映斜坡高差。覆盖不同足端高度、航向、滚转和俯仰。
3. 覆盖全量、非连续索引、空选择和非有限输入。记录扫描关闭时的观测维数与每步查询次数，供后续回归对照。
4. 用 61 个不同的高度值和一组包含命中、未命中的有效掩码，验证 `61 点 → 9 × 9 → 61 点` 往返后的数值、点序与有效掩码一致。检查布局掩码包含 61 个位置，中心有六个邻居且均距中心 `0.12 m`。
5. 在足端位置可区分的用例中重排已配置的足端，验证两个扫描张量的足维按解析顺序同步重排。用不同足端数量的合成输入校验张量形状和观测维数推导。
6. 固定足端 XY 和基座姿态，仅改变足端 Z，验证射线起点和命中距离保持一致，而相对高度随之更新。用解析地面覆盖量程边界、超量程及 `base` 平面上方无交点的情况。

### 完成标准

同一状态得到固定点序和一致结果。紧凑与二维布局往返后保留数据、点序及有效性，六邻域索引通过距离校验。平地高度、量程边界和无效点符合第二章的约定。关闭扫描时，原有物理字段与基线一致，扫描字段为 `None`，射线查询次数为零。

## 五、阶段 2：双后端地形采集

### 目标

让同一套扫描实现支持 MuJoCo 和 Isaac Sim。用 ANYmal C 完成地形求交对照，用 Go1 验证换机型只需更换配置。

### 实施方案

1. **MuJoCo。** 从同一次 `get_state()` 读取足端和基座状态，在各环境的当前地形上做方向射线查询。高度场使用 `mj_rayHfield`，其他地面按碰撞几何选求交方式，查询限定地面 geom。已知水平面可用解析求交。 [MuJoCo 查询](../../envs/simulators/mujoco.py) · [高度场与外围平地](../../envs/simulators/mujoco_terrain.py) · [MuJoCo 射线接口](https://mujoco.readthedocs.io/en/3.11.0/APIreference/APIfunctions.html#ray-casting)
2. **Isaac Sim。** 建立可复跑的 ANYmal C 配置，校验关节、足序及足端参考点。将射线变换到世界坐标，与共享地图的碰撞地表求交，包括邻块和外围平地。先用 PhysX 场景查询验证，再按吞吐决定是否实现设备端的批量网格求交。局部读取只扫描选中的环境。 [Isaac 状态读取](../../envs/simulators/isaac_sim_runtime.py) · [共享网格查询](../../envs/simulators/isaac_sim_terrain.py)
3. 两端分别验证默认平地与自定义碰撞地面。在 Isaac 按地面 prim 筛选交点，必要时用 `raycast_all` 跳过先命中的机器人。保持现有 `get_ground_heights(xy, env_ids)` 服务竖直高度查询，足端扫描使用独立的方向求交入口。对照命中位置、距离、相对高度和掩码，覆盖三角形内部、接缝、外围、越界与近乎平行的射线，并检查首次 reset 和局部 teleport 后的查询同步。 [项目射线验收](../../tests/manual/verify_isaac_terrain.py) · [PhysX 场景查询](https://docs.omniverse.nvidia.com/kit/docs/omni_physics/110.1/extensions/runtime/source/omni.physx/docs/dev_guide/scene_queries.html)
4. 在两端用 Go1 的足端映射运行平地和斜坡扫描，至少覆盖一种非默认布局或量程。校验足端参考点、射线位置、输出形状和数值。

### 完成标准

ANYmal C 在两端通过独立射线对照，验收记录注明误差容差、边界点的有效性及超差位置。Go1 在两端通过配置接入同一个扫描 term。无法可靠查询的自定义地面在初始化时报出明确的配置错误。

## 六、阶段 3：观测与训练集成

### 目标

将足端扫描接入现有观测框架，使训练、评估、回放和续训都使用一致的观测定义。

### 实施方案

1. 注册 `foot_terrain_heights` 和 `foot_terrain_heights_valid`，校验相对高度、裁剪缩放、无效填充、展平顺序和策略输入切片。用重排后的足序验证观测切片同步重排，并在恢复检查点时识别足序变化。验证启用扫描观测但未配置 simulator 状态 term 时，能在构建观测阶段报错。两侧均关闭时，原有观测维数维持基线。
2. 验证全量和局部 reset、失败回滚及检查点续训。终止帧保留 reset 前的扫描，下一回合按新姿态和地形重扫选中的环境。覆盖摩擦随机化与课程换地形。Isaac 跨块时，课程继续按回合出生时的分配结算。
3. ANYmal C 在两端各执行一次真实 PPO 短训，验证评估和回放。Go1 在两端执行 reset 和 step 冒烟测试，核对观测维数、足序和有效掩码。播放时叠加显示选中环境各足端的采样点与有效性。日常训练记录有效比例等聚合值。
4. 在 PPO 短训中用相同环境数、地形和控制步长，对比关闭扫描与开启几何查询扫描时预热后的控制步吞吐。记录配置、点数、预热长度和测量步数，作为两个扩展及阶段 4 的复测基线。

### 完成标准

两个 obs term 按配置进入策略，PPO 产生有限的观测、损失和参数更新。局部 reset 只更新选中行，终止帧可继续使用。恢复后同一地形和姿态产生一致扫描，回放落点与地面对应。两端均有可复测的扫描启闭吞吐基线。落足和越障收益另用固定种子与命令做对照训练。

## 七、扩展 A：采集时序与缓存

### 目标

让扫描具有独立于控制步的采样频率、可配置的交付延迟和逐环境缓存，为高程图的异步更新提供统一时序。

### 实施方案

1. 先在仿真中用固定采样周期和固定延迟验证机制。按仿真时钟调度，分别记录每帧的采集时间和可用时间。重复读取同一时刻的状态应复用已有采集结果。
2. 按环境缓存已采集帧及其姿态、有效性和时间戳，读取时使用最近一帧已可用的数据。首帧尚未可用或数据超龄时输出无效掩码。明确缓存的是整帧扫描还是可供当前射线重新查询的地表。扩展 B 的地图输入由当前足端射线查询最新可用地图。
3. 局部 reset 清理选中环境的旧帧和待交付数据，失败时随 reset 回滚。检查点保存可复现后续采集所需的时钟、待交付帧和缓存。

### 完成标准

采样和交付时刻符合配置。重复读取、不同采样与控制频率、首帧等待、超龄、局部 reset、回滚和检查点恢复均有对照用例。零延迟且每控制步采样时与同步基线一致。

## 八、扩展 B：高程图与实机感知

### 目标

保留既有观测定义，用相机或雷达生成的高程图替换几何查询。首个实机验证使用 ANYmal C，其他机型按各自的传感器内参、安装外参、量程、频率和足端运动学接入，复用建图后的射线查询与观测接口。

### 实施方案

1. 复用扩展 A 的采样时序、帧龄和缓存机制。对照虚拟相机与实机数据逐步加入高度噪声、采样位置偏差和局部缺测，明确随机状态的恢复规则。
2. 在少量 Isaac 环境中复用 URDF 的四个深度光学坐标系，配置 D435 内参、量程与频率。将深度反投影成点云，按采集位姿融合为局部地表。读取时将当前的 `−base Z` 射线变换到地图坐标系，与由有效地图数据重建的地表求交，再按第二章计算高度差。采用 2.5D 高程图时，沿射线与高程表面求交，破碎边缘和缺测区域按有效性规则处理。若实机采用 Bpearl，按实际装配与扫描参数验证。 [ANYmal C URDF](../../assets/anymal_c/URDF/urdf/anymal.urdf) · [Isaac Sim 相机文档](https://docs.isaacsim.omniverse.nvidia.com/6.1.0/sensors/isaacsim_sensors_camera.html)
3. 实机先在平地与已知缓坡上校验外参、时间戳、机身位姿和足端运动学，再测试停走、转向和腿部遮挡。台阶边缘与立面的几何验收沿用地形计划中的台阶扩展。 [台阶地形扩展](terrain_development_plan_zh.md#扩展-b台阶地形)

### 完成标准

三种数据来源沿用同一足序、射线布局、量程和相对高度定义，并按各自的采集结果提供逐点有效性。在平地与已知斜坡上对照滚转时的命中位置和相对高度，分别记录有效点的误差和缺测比例。遮挡、视场和延迟在本扩展验收。

## 九、阶段 4：性能与交付

### 目标

量化几何查询在常用训练规模下的开销，以及虚拟相机和实机高程图的更新频率、延迟与有效覆盖率。确定可复跑的训练配置和验收入口。

### 实施方案

1. **训练路径。** 对照阶段 3 的吞吐基线复测。双后端均使用仿真地面几何查询，比较启闭扫描时的初始化时间、控制步吞吐、局部 reset 时间和峰值内存或显存。先测 1 和 16 环境，再测各后端常用规模，Isaac 增测 1024 环境。
2. MuJoCo 单独测量 CUDA 策略下的 CPU 往返和逐环境射线求交，Isaac 记录批量求交的位置和成本。默认蜂窝布局在 1024 个四足环境中每帧查询 249,856 束。记录实际间距和层数。若需降频，补齐帧龄、坐标对齐和局部 reset 后首帧的处理与验证。
3. **感知路径。** 在少量 Isaac 环境中测试虚拟相机建图，并在单台 ANYmal C 上验证实机高程图。分别记录高程图更新频率、从传感器采集到策略可用的延迟，以及四足采样点的有效比例。覆盖平地、移动和腿部遮挡场景。
4. 交付 ANYmal C 双后端训练示例、Go1 双后端复用示例、验收脚本和性能记录。训练记录注明机型、硬件、点数、控制步长、预热和运行长度。感知记录注明传感器配置、测试场景和延迟测量方法。

### 完成标准

双后端训练配置通过功能验收，并达到基于阶段 3 数据确定的吞吐与资源预算。虚拟相机和实机高程图各有更新频率、延迟和有效覆盖率的测量记录。Windows 上 Isaac 验收进程的实际退出码为 `0`。使用交付配置和脚本可复跑。
